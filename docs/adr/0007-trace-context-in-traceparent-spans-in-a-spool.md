# Trace context travels in TRACEPARENT, and spans are collected in a spool directory

A build trace is made of spans from many short processes: the `gocached trace` commands a CI script runs, hundreds of toolexec processes and one `GOCACHEPROG` process per go command. They must end up in one trace without a long-running service.

**Context.** The current span is the standard `TRACEPARENT` (and `TRACESTATE`) environment variable, read and written with `go.opentelemetry.io/contrib/propagators/envcar`, following the OpenTelemetry environment-variable carrier spec. `go` passes its environment to tools and to `GOCACHEPROG` unchanged, so every process sees the span it should be a child of. Scripts move between spans with `export TRACEPARENT=$(gocached trace begin ...)` and `$(gocached trace end)`, as with otel-cli, which keeps each shell's (or each `&` job's) current span in its own environment and lets the two tools be mixed. We rejected keeping a stack of open spans in a shared file, which breaks on parallel jobs, and an `init` that prints shell code to `eval`, which is shell-specific.

**Parent and root.** A `TRACEPARENT` that is already set is always the parent, so a trace started by Jenkins or Buildkite contains the build. Without one, `begin` creates the root span. `GOCACHED_TRACE_KEY`, any string, makes the outermost span's ID (and, without a parent, the trace ID) a hash of the key, so a rerun of the same job gets the same span; inner span IDs are random. A `begin` that finds its span still open, left by a crashed run, warns and restarts it with the current time.

**Spool.** Each process writes its finished spans as one OTLP JSON file into the trace session directory, through a temp file and rename (about 1 ms per file on Windows). `trace end --export`, `trace exec` at the outermost level, and `trace export` read the directory, send everything through an exporter (OTLP/HTTP or a file; the interface leaves room for others) and empty it. A local collector process was rejected: it needs a port and someone to stop it, and loses spans when it dies, while files survive a killed job and can be exported afterwards.

**Session directory.** `GOCACHED_TRACE_SESSION_DIR` if set, used as is, with a warning if it is not empty. Otherwise a subdirectory of `GOCACHED_TRACE_BASE_DIR` (default `<tmp>/gocached-trace`) named after the hash of `GOCACHED_TRACE_KEY`, or after the trace ID. It is created when missing. `trace export --all` scans the base directory only.

**Fail open.** Tracing never blocks or alters go's own build, even if every tracing component is broken (say, a future go version breaks the parsing). A misused `trace` command (a bad flag, an unknown subcommand) fails with a non-zero exit, but every `trace` command warns on stderr and exits 0 on its own runtime errors (`trace exec` returns the child's exit code), and `begin`/`end` print the unchanged `TRACEPARENT` when they cannot open or close a span, so the shell variable stays valid.
